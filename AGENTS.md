# Working commands

- Node.js 24+; `npm ci` installs the locked SDKs and development tools.
- `npm start` loads .env, verifies Relay/Supabase access, and runs the receiver/worker in stylist mode. `CONVERSATION_MODE=connection npm start` runs the fixed hello test without Gemini.
- `npm run relay:connect` runs official signed forwarding and writes the secret privately to `.env`, printing only safe status. Use this for agent-run setup. The original `npm run relay:listen` prints a private signing secret/event content, so run that version only in the user's terminal. First use may download the official CLI.
- `npm run check` checks TypeScript without emitting files.
- `npm run demo -- hello` demonstrates the connection acknowledgement. Another input uses a fixed sample Gemini plan and mock catalog, without API calls.
- `npm run smoke` verifies hello and empty-input handling. It does not verify Gemini or Relay.
- `npm test` runs all synthetic tests, including Relay durability, model validation, the typed Stylist-to-Shopper handoff, grounded Shopper citations, wardrobe review, pathways, and scoped memory; it needs a temporary localhost port. A passing suite does not prove live Gemini, Relay, or Supabase behavior.
- `npm run shopper:search -- '<JSON request>'` uses Gemini Google Search grounding from the local `.env` key to discover cited product pages. It does not verify stock or place orders.
- `npm run voice:setup -- --websocket` creates/reuses the private ElevenLabs agent with a blocking Stylist client tool, saves ignored local settings and enables WebSocket calls. Restart the backend and keep Relay forwarding running; no public voice tunnel is required. The legacy URL argument selects HTTP mode and requires an authorized public SSE origin.
- `npm run voice:check` checks Relay calling, ElevenLabs credentials, decoding, private agent/tool settings and local health. WebSocket configuration and a real synthetic provider hello/tool/audio probe passed; 13 audio chunks were generated. The user reported repeated silent phone calls under HTTP despite recorded replies, so do not claim audible success based on transcripts or provider probes. Fresh phone audibility and the full camera walkthrough remain pending. Safe audio logs contain counts only. The official bridge runtime WebSocket-constructor injection hook is supported by pinned 0.1.1 but omitted from its declaration; keep the compatibility test covering actual bridge audio, ping/pong and tool result delivery.

- `npm run voice:tunnel` is legacy HTTP-only and is stopped in WebSocket mode. It uses the localhost.run service explicitly approved by the user on October 4, 2026; validates callback authentication, reconnects SSH, and serializes/retries rotating-origin updates. Do not launch a tunnel automatically from backend startup or alongside WebSocket configuration.
